# 클로드 모션그래픽 프롬프트 — 학습 노트

출처: 빌더 조쉬 「클로드 모션그래픽 한글 프롬프트 100」
원문: https://tuemarz.notion.site/100-401137c926d5812fa1e8c56de870617b

원문을 그대로 옮긴 사본이 아니라 정리한 노트입니다. 프롬프트 100개의 전체 문장이 필요하면 원문을 보세요.
여기에는 그 프롬프트들이 **왜 잘 나오는지**, 그리고 **같은 방식으로 새 프롬프트를 쓰는 법**을 담았습니다.

---

## 1. 프롬프트 구조 (항상 이 순서)

```
<입력>   (선택) 먼저 사용자에게 받아야 할 파일·정보: 로고 SVG, 사진, 음악 등
<방향>   길이 · 이름/문구 · 팔레트 · 글꼴 · 핵심 연출 한 가지 · "마지막 프레임 = 첫 프레임"
<구성>   BPM, 마디 수, 마디별로 무엇이 일어나는지
+ 공통 블록 (<제작> <금지> <시작>)
```

`[대괄호]`만 바꾸면 되는 템플릿 방식입니다. 색에는 항상 기본값을 같이 적습니다. 예: `[포인트 색 · 기본 #FF5A1F]`

## 2. 공통 블록 (모든 프롬프트 뒤에 붙임)

```
<제작>
1. HTML 파일 하나, [세로 1080x1920 / 가로 1920x1080]. 모든 스타일은 window.seek(t) 안에서 시간만으로 계산한다: CSS 애니메이션·타이머·프레임 사이에 남는 상태 금지.
2. 스프링은 닫힌 형태(시간의 함수)로 쓰고, 목표가 여러 번 바뀌면 바뀔 때마다 스프링을 하나씩 더해서 계속 시간의 순수 함수로 유지한다. 오버슈트는 아주 살짝만.
3. 빠르게 움직이는 것에는 속도 방향으로 모션 블러.
4. Playwright로 60fps 렌더, 프레임마다 서브프레임 3장을 ffmpeg tmix로 섞어 모션 블러를 만들고 output.mp4로 저장한다. 소리가 필요하면 Web Audio(OfflineAudioContext)로 박자마다 킥, 장면 전환마다 효과음을 코드로 만들어 합친다.
5. 전체 렌더 전에 박자마다 한 프레임씩 뽑아 직접 보고, 복잡하거나·박자에서 벗어나거나·겹치거나·읽기 어려운 곳을 고친 뒤 렌더한다.
6. Math.random 금지(매번 같은 결과).
</제작>
<금지>
파티클 폭발, 글로우, 렌즈 플레어, 카메라 흔들림, RGB 분리, 크로스페이드·블러 인, 흔한 그라데이션, 통통 튀는 이징, 0.5초 넘게 멈춘 화면, 화면 구석의 작은 라벨·숫자, 템플릿처럼 보이는 모든 것.
</금지>
<시작>
콘셉트를 한 줄로 정하고 박자별 스토리보드를 먼저 보여 준 다음, 나한테 더 묻지 말고 끝까지 만들어서 output.mp4 를 줘.
</시작>
```

### 이 블록이 하는 일 (쉽게 풀면)
- **seek(t) 순수 함수**: 영상의 어느 순간이든 시간 값 하나로 똑같이 다시 그릴 수 있습니다. 그래서 프레임 단위로 정확하게 렌더할 수 있고, 매번 같은 결과가 나옵니다.
- **닫힌 형태 스프링**: 물리 시뮬레이션을 매 프레임 쌓아 가지 않고, 시간 공식 하나로 계산하는 탄성 움직임입니다. 위와 같은 이유로 결과가 항상 같습니다.
- **서브프레임 3장 + tmix**: 진짜 카메라처럼 보이는 모션 블러를 만드는 방법입니다.
- **박자별 프레임 점검**: 전체를 렌더하기 전에 스스로 확인하게 해서 다시 만드는 비용을 줄입니다.

## 3. 좋은 결과를 만드는 디자인 원칙 (100개에 공통)

1. **한 가지가 끝까지 이어지게**: 컷이나 페이드를 쓰지 않고, 앞 요소가 변해서 다음 장면이 됩니다.
   예: 선 → 로고 → 아이콘 → 밑줄, 버튼 → 로딩 → 체크 → 카드, 점 → 밑줄 → 버튼.
2. **처음과 끝이 같게(루프)**: 마지막 프레임 = 첫 프레임. 반복 재생이 자연스럽습니다.
3. **박자가 기준**: 대부분 120 BPM(고급스러운 톤은 96 BPM)이고, "박자마다 무언가 일어난다"를 지킵니다. 4박이 1마디이고, 120 BPM에서는 1마디가 2초입니다.
4. **색은 절제해서**: 배경(오프화이트/먹색/크림) + 글자색 + **포인트 색 하나**만 씁니다. 포인트 색은 "지금 봐야 할 것"에만 씁니다.
5. **글꼴**: Pretendard(한글), 숫자는 Geist, 코드는 Geist Mono, 영문 포스터는 Archivo를 씁니다.
6. **등장 방식**: 페이드 대신 "마스크 선에서 올라옴", 늘어남·접힘·미끄러짐·뒤집힘·원형 와이프를 씁니다.
7. **숫자**: 자릿수마다 세로 롤러로 굴러가게 하고, 구석에 작게 두지 않고 크게 보여 줍니다.
8. **카메라**: 지금 중요한 요소가 화면을 채우도록 줌하거나 따라갑니다(흔들림 금지).
9. **UI 데모**: 커서나 터치 원이 실제로 클릭·드래그·입력하면서 변화를 이끕니다.
10. **무작위 대신 고정 규칙**: 흩어진 점도 고정 시드나 정해진 각도로 배치합니다.

## 5. 새 프롬프트를 쓰는 법 (우리 프로젝트용)

1. **연출 한 줄 정하기**: "무엇이 무엇으로 변하며 이어지는가?" 예: `가격표 → 장바구니 버튼 → 영수증 → 다시 가격표`
2. **팔레트 3색 + 포인트 1색, 글꼴** 정하기
3. **BPM과 마디 수 정하기**: 15초 ≈ 120 BPM 8마디. 마디마다 일어날 일을 한 줄씩 적기
4. **"마지막 프레임 = 첫 프레임"** 문장 넣기
5. **공통 블록** 붙이기 (세로 1080x1920 또는 가로 1920x1080 선택)

## 6. 고칠 때 팁
- 결과에서 거슬린 것은 `<금지>`에 한 줄 추가합니다. 예: "글자가 화면 밖으로 잘리는 것"
- "하지 마"로 끝내지 말고 대안까지 적습니다. 예: "페이드 대신 마스크 선에서 올라오게"
- 수정 요청은 한 번에 한두 개만, 짧게 합니다. 예: "3마디를 두 배 빠르게"
- 다시 렌더하기 전에 "박자마다 한 프레임씩 뽑아서 보여 줘"로 먼저 확인합니다.
- 클로드 코드에서 Opus, effort 최대로 돌립니다. 클로드 앱에서는 HTML 미리보기를 화면 녹화하면 됩니다.

## 7. 이 환경에서 실제로 돌릴 때 확인할 것
- Chromium, Playwright, ffmpeg, Node 22가 모두 설치되어 있습니다(확인 완료). 따라서 이 환경에서 바로 mp4를 렌더할 수 있습니다.
- Pretendard·Geist 글꼴은 웹에서 불러오거나 로컬에 설치해야 합니다. 네트워크 정책 때문에 막힐 수 있습니다.
